## UPDATE — 2026-06-14 20:28 UTC: Root Cause CORRECTED

**Hostinger support (Kodee) found the real issue: Nginx config conflict on the VPS, NOT a Hostinger CDN/WAF layer.**

### What was actually wrong:
1. **Two conflicting nginx vhosts** both claiming `base66.cloud`:
   - `/etc/nginx/sites-enabled/base66.cloud`
   - `/etc/nginx/sites-enabled/buildany`
   - This caused nginx to randomly pick one, ignoring the other
2. **Wrong proxy port:** Nginx was proxying to `localhost:3000`, but the PM2 app runs on `3001`
3. **The Let's Encrypt cert IS on the VPS** at `/etc/letsencrypt/live/base66.cloud/` — we incorrectly assumed it was upstream

### Fix applied:
```bash
sudo rm /etc/nginx/sites-enabled/buildany
sudo sed -i 's/proxy_pass http:\/\/localhost:3000;/proxy_pass http:\/\/localhost:3001;/' /etc/nginx/sites-enabled/base66.cloud
sudo nginx -t && sudo systemctl reload nginx
```

### Verification:
- `curl -k https://127.0.0.1/ -H "Host: base66.cloud"` returns HTTP 200 with full BuildAny homepage HTML ✅
- The 502 error the user saw was likely a transient state before nginx fully reloaded

### Lesson learned:
The "nginx stop test" that seemed to prove an upstream layer was actually flawed — the conflicting vhosts meant nginx may have auto-restarted or the second vhost kept running. Always check for duplicate configs before assuming upstream proxies!

## BuildAny Quick Diagnostic Commands (2026-06-15)

### 3-Command Status Check
When troubleshooting BuildAny issues, run these 3 commands in order:

```bash
# 1. Check if port 3000 is listening
sudo ss -tlnp | grep 3000

# 2. Detailed PM2 process info
pm2 show buildany

# 3. Summary of all PM2 processes
pm2 list
```

### Expected Healthy Output
- `ss` shows: `LISTEN 0 511 *:3000 *:* users:((next-server, ...))`
- `pm2 show` shows: `status: online`, `restarts: 0`
- `pm2 list` shows: `buildany` with green `online` status

### TypeScript Build Notes
- `tsc --noEmit` may fail with drizzle-orm type errors (TS2769)
- `npm run build` passes because `ignoreBuildErrors: true` is set in `next.config.ts`
- For production: use `npm run build` (not `tsc --noEmit`)
