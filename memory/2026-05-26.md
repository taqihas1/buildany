
## 2026-05-26 (midnight) - CarSearchScreen Debugging

**Problem**: `CarSearchScreen.tsx` has a JSX nesting bug at line 272. The `selectedSearchRadius` active filter chip is placed INSIDE the `{zipCode && (...)}` conditional block, causing `SyntaxError: Unexpected token, expected ","` because JSX expressions can only contain a single root element.

**Root cause of the mess**: Previous Python fix scripts used fragile string replacement patterns that either:
1. Failed silently ("WARNING: Could not find nested chip pattern")
2. Corrupted the file (commit 33efccd had 226 deletions)
3. Deleted large chunks of the file
4. Had Python f-string syntax errors when JS curly braces conflicted with Python f-string syntax

**Current state of the file (as of commit 33efccd)**:
- `selectedSearchRadius` state uses `userLocation` BEFORE it's declared: `useState(userLocation.radius || 50)` — this is a ReferenceError
- `selectedSearchRadius` chip is nested inside `{zipCode && (...)}` block
- `useEffect(() => { loadListings(); }, []);` has wrong deps
- Zip input has `returnKeyType="done"` instead of `"search"`
- The `DAYS_ON_MARKET` import from `carApi.ts` was added, but the `DAYS_ON_MARKET` constant itself is missing from `carApi.ts`

**What worked**: Writing a COMPLETE fresh version of `CarSearchScreen.tsx` to a file (`CarSearchScreen_fixed.tsx` in workspace) with ALL fixes applied:
1. `selectedSearchRadius` initial value: `useState<number | null>(null)`
2. `selectedSearchRadius` chip moved OUTSIDE the `zipCode` block
3. `useEffect` deps fixed to `[loadListings]`
4. `returnKeyType="search"` on zip input
5. `DAYS_ON_MARKET` array included in imports (but carApi.ts still needs the export)

**Lesson learned**: For complex JSX files with nested conditionals, do NOT use string replacement scripts. They fail silently or corrupt files. Instead:
- Write the complete corrected file to workspace
- Have user download and replace the entire file
- Or use line-by-line processing with explicit structural checks
