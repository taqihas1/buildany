## 2026-06-09 Hermes Orchestrator Architecture (06:30-07:00)

### Core Decision: Hermes is the Master Orchestrator
- User decided: Hermes IS the OpenClaw orchestrator — not a plugin, not external, but the internal engine inside BuildAny
- Swarm tab IS OpenClaw working — it shows the agents in action
- OpenClaw's role: Internal orchestrator, not external collaboration tool

### Problem Discovered: Chat Bypasses Agents
- The chat was generating code directly via LLM, creating tasks in DB, but agents were NEVER activated
- All 20 tasks in DB were status `pending` — agents sat idle with 0 active, 0 done, 0 failed
- The chat and agents were completely disconnected

### Solution: Hermes Orchestrator API
- Created `/api/orchestrate` route with server-side `HermesOrchestrator` class
- The orchestrator actively manages the full lifecycle, not just passively tracks

### Orchestrator Flow (4 Phases)
1. **DESIGN**: Hermes analyzes prompt, creates design plan, reports to chat
2. **BUILD**: 
   - Decomposes into tasks
   - Creates agents and assigns tasks
   - Agents execute in parallel using LLM
   - Combines outputs into final app
   - Saves to `project_files` table (index.html + __preview.html)
   - Reports each phase to chat
3. **TEST**: 
   - Spin up Test Agent
   - Review code, check bugs, quality score
   - Report results to chat
4. **REPORT**: 
   - Final status to chat
   - User checks Code and Preview tabs

### Status Reporting
- All status messages go into `conversations` table with role `system`
- They appear in the AI Chat panel in real-time
- Messages like: "🔍 Hermes: Analyzing...", "⚡ Hermes: Decomposing...", "🚀 Hermes: 3 agents executing..."

### Code Structure
- `HermesOrchestrator` class with methods: `design()`, `build()`, `combine()`, `test()`, `finalize()`, `report()`
- Runs async — returns immediately to user, continues in background
- `generate` route now forwards to `/api/orchestrate` instead of direct LLM calls

### Key Files Created/Modified
- `/api/orchestrate/route.ts` — Main orchestrator API
- `/api/generate/route.ts` — Now forwards to orchestrator
- `/api/execute-tasks/route.ts` — Task execution endpoint (may be superseded by orchestrator)

### 1. Tasks Not Assigned to Agents (SwarmDashboard)

### 3. Missing `project_id` on agents table
- Schema was missing `project_id` column on `agents` table
- Added via ALTER TABLE on the VPS directly
- Also fixed orchestrator to insert `projectId` when creating agents

### 4. Status Mismatch: "done" vs "completed"
- Orchestrator set `status: "done"` but schema used `completed`
- Fixed in `src/app/api/orchestrate/route.ts`

### 5. Status Messages Wrong Order
- AIChatPanel had two separate useEffects watching `files` and `tasks`
- Race condition: code message appeared before decomposition message
- **Fix**: Combined into single useEffect with proper ordering (decomposition first, then code)

### 6. Raw Markdown in Status Messages
- Status messages showed `**Wiki tab**` as raw text
- **Fix**: Added regex to strip markdown: `content.replace(/\*\*/g, '').replace(/`/g, '')`

### 7. Wiki/Research Not Showing
- Both panels just showed "No data" without checking if backend was actually returning errors
- **Fix**: Added `console.error` logging in catch blocks and better loading states
- Wiki API worked fine — just no data in DB for this project yet
