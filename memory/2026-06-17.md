### Integration Architecture Options (3 paths)

**Option A: Hermes Gateway API (port 8642)**
- Hermes runs as standalone Docker container with HTTP API
- BuildAny calls `POST http://localhost:8642/chat` with user messages
- Hermes can call back to BuildAny tools via `/api/hermes-tool` routes
- **Pros:** Hermes is the true agent, handles memory/skills internally, proper agent loop
- **Cons:** Requires Docker container to stay running, tool callback complexity

**Option B: BuildAny Proxies to Hermes (current `/api/hermes-chat`)**
- BuildAny Next.js route proxies chat to Hermes container
- Hermes runs in Docker, BuildAny routes all chat requests to it
- **Pros:** Simple proxy, no gateway mode needed
- **Cons:** Hermes doesn't know about BuildAny tools natively, just chat

**Option C: Hermes Embedded in BuildAny**
- Import Hermes as a module/library inside BuildAny process
- Hermes runs as part of the Next.js app
- **Pros:** Tightest integration, no network hop
- **Cons:** Hermes may not be designed for embedding, dependency hell

## BuildAny TypeScript Strict Mode — Critical Patterns

### Type Annotation Required Everywhere
BuildAny Next.js uses strict TypeScript. **Every** function parameter needs explicit types:
```typescript
// ❌ WRONG:
async function callTool(name, params) { }
export async function POST(req) { }
async createProject(params) { }

// ✅ CORRECT:
async function callTool(name: string, params: any) { }
export async function POST(req: NextRequest) { }
async createProject(params: { prompt: string; name?: string }) { }
```

### Projects Schema (SQLite/Drizzle)
- **Table:** `projects` in `src/lib/db/schema.ts`
- **Fields:** `id`, `name` (notNull), `description`, `status`, `type`, `userId` (notNull), `createdAt`, `updatedAt`
- **NO `prompt` field** — use `description` or `name` instead
- **Status values:** `"draft"`, `"wiki"`, `"coding"` (normalized)
- **Timestamp mode:** `{ mode: "timestamp" }` with `$defaultFn(() => new Date())`
- **Do NOT pass** `new Date()` manually — causes type mismatch

### Middleware Quote Bug
- **Issue:** sed with quotes produces broken syntax: `'/api/hermes-chat",` or `"/api/hermes-tool',`
- **Fix:** Use Python3 for any file edit involving quotes or brackets:
```bash
python3 -c "
import re
with open('src/middleware.ts','r') as f: c=f.read()
c=c.replace('old', 'new')
with open('src/middleware.ts','w') as f: f.write(c)
"
```

## VPS Terminal Patterns — Learned the Hard Way

### NEVER use `curl <url> | node` on VPS
- Terminal prompt echo injects text into stdin stream
- Causes `SyntaxError: Invalid or unexpected token` or `Unexpected identifier 'root'`
- **Always:** `curl -o /tmp/file.js <url>` then `node /tmp/file.js`

### NEVER use sed with `[]` brackets on VPS
- `sed: -e expression #1, char 18: unknown option to 's'`
- Brackets in regex need escaping or different delimiter
- **Always use Python3** for edits involving special characters

### Python3 is the reliable file editor
```bash
python3 -c "
with open('file.ts','r') as f: c=f.read()
c=c.replace('old-pattern', 'new-pattern')
with open('file.ts','w') as f: f.write(c)
"
```

### SSH from assistant to VPS is DEAD
- `ssh root@srv1730121.hstgr.cloud` — times out consistently
- **All VPS commands must be run by user directly**
- GitHub repo serves as source of truth for file changes
