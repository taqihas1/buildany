## Custom Dev Client APK — Build Attempts & Final Solution

### expo-dev-client Installation
- Installed `expo-dev-client` (SDK 54.0.0 compatible) in /tmp/Carbuyingassistant via `npx expo install expo-dev-client`
- Added packages: expo-dev-client, expo-dev-launcher, expo-dev-menu
- This enables a custom development client that can scan QR codes and stream JS bundles live — unlike generic Expo Go which can't load custom native modules

### Debug Build Attempts — All OOM-Killed
- `./gradlew :app:assembleDebug --max-workers=1 --no-daemon` — SIGKILL during `:app:mergeDebugNativeLibs` (CMake native compilation)
- Second attempt — SIGKILL during `:app:mergeReleaseAssets` / resource processing
- Even release APK build (`./gradlew :app:assembleRelease --max-workers=1 --no-daemon`) — SIGKILL during `:app:processReleaseResources`
- Root cause: Native C++ compilation (CMake for multiple modules: reanimated, screens, etc.) + simultaneous resource merging uses too much RAM on our 2-core / ~7GB machine

### Final Solution: bundletool AAB → APK Conversion
- Since AAB release build ALREADY succeeded (cached compilation), used `bundletool` to extract APK without recompiling anything
- Downloaded bundletool 1.18.1 from GitHub releases
- Steps:
  1. `java -jar bundletool.jar build-apks --bundle=app-release.aab --output=app.apks --mode=universal`
  2. `unzip app.apks -d apk_output/`
  3. Result: single universal APK at `apk_output/universal.apk`
- APK size: 30,941,604 bytes (30.9MB) | AAB size: 24,989,256 bytes (23.8MB)
- APK is signed with release keystore, includes `expo-dev-client` baked in

## Dev Client APK — Why QR Code Didn't Work
- The APK created via bundletool (from AAB) was built BEFORE `expo-dev-client` was installed
- bundletool just extracts/repackages the existing AAB — it doesn't add new native modules
- So the APK had NO dev client launcher/menu baked in
- That's why user said "did not work" when trying to scan QR code — the app had no QR scanner capability!
- **Lesson**: If you need a dev client APK, you MUST build from source AFTER installing `expo-dev-client`, OR use `eas build --profile development` with expo-dev-client in dependencies
- bundletool workaround is only useful for distributing release builds, not dev clients
