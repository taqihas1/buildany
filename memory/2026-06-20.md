## BuildAny Kelly Chat - Frontend Bug Fixes (05:18-08:39 GMT+8)

### Problem: Kelly replies to first message but goes silent on follow-ups
- User sends "hi" → Kelly replies
- User sends second message → **no response**
- Chrome DevTools shows `POST /api/hermes-chat 400 (Bad Request)`

### Problem 2: Message duplication in chat UI
- User types message once → appears 2-3 times in the chat panel
- React error #418 (hydration mismatch) in console

### Root Cause 1: Stale closure in `useHermesChat` hook
- `messages` was in `useCallback` dependency array
- First message works because `messages` is empty
- Second message fails because `messages` is stale (empty array captured at creation time)
- API receives empty history → Kelly has no context

### Root Cause 2: Module-level counter causing hydration mismatch
- `let messageCounter = 0` at module scope
- Server render: counter starts at 0, increments → IDs like msg-1, msg-2
- Client render: counter starts at 0, increments → same IDs BUT different sequence if SSR vs CSR
- React hydration mismatch → Error #418
- Also caused message duplication due to double-render recovery

### Root Cause 3: isSubmittingRef missing
- `handleSubmit` could fire multiple times before `setIsLoading(true)` took effect
- Race condition: click submit → React re-renders → handler fires again

### Fixes Applied

**1. Fixed `useHermesChat.ts` (hook)**
- Removed `messages` from `useCallback` dependency array → `[]`
- History is now built from a `useRef` instead of state closure
- No more stale closure on follow-up messages

**2. Fixed `AIChatPanel.tsx` (component)**
- Replaced module-level `messageCounter` with `useRef` inside component
- Server and client now generate identical IDs → no hydration mismatch
- Added `isSubmittingRef` to block concurrent submissions
- User + loading messages added in **single** `setMessages` call (atomic)

**3. Fixed `/api/hermes-chat/route.ts` (API)**
- API now accepts BOTH formats: `message`/`history` AND `query`/`messages`
- Returns both `reply` and `response` for frontend compatibility

### Key Lessons
- **Never put `messages` state in `useCallback` deps** — causes stale closures
- **Never use module-level counters for React IDs** — causes hydration mismatches
- **Always use `useRef` for submission guards** — prevents double-submits
- **OpenClaw `write`/`edit` tools change LOCAL sandbox, NOT the user's VPS** — user must run commands on VPS to actually apply changes
- **Heredocs can get mangled** — use `python3 -c` for reliable file writes on VPS
