### Root Cause 2 — Backtick Corruption in hermes-chat/route.ts
- File: `src/app/api/hermes-chat/route.ts`
- Line 29: `const KELLY_SYSTEM_PROMPT = \`;` — backticks corrupted into `\;`
- **Why it happened:** Writing multi-line content via `cat << 'EOF'` on VPS caused backtick escaping issues. Also later attempts with Python triple-quoted strings failed due to shell history expansion (`!`) and backtick interpretation.
- **Attempted fixes:**
  1. `sed -i` replacement — worked temporarily but Turbopack cached old version
  2. `cat << 'TSEOF'` heredoc — Python script injected `\` before backticks, breaking template literals
  3. Clearing `.next/` and `.turbo/` caches — Turbopack still pulled from deeper system caches
  4. Nuclear cache clear — `rm -rf .next .turbo node_modules/.cache /tmp/turbopack* /tmp/next* ~/.cache/turbopack ~/.cache/next` — **THIS WORKED**
  5. **Final fix:** Moved `KELLY_SYSTEM_PROMPT` to separate file `src/lib/kelly-prompt.ts` with double quotes instead of backticks, imported into route.ts. This bypassed Turbopack's parser bug entirely.

### Key Lesson
- **Never use backticks in heredoc scripts on VPS** — they get corrupted. Use double quotes or escape aggressively.
- **Turbopack caches are deeper than expected** — clearing `.next/` alone is not enough. Must also clear `/tmp/turbopack*`, `/tmp/next*`, `~/.cache/turbopack`, `~/.cache/next`.
- **Small chunks > big scripts** — User explicitly requested small chunks after the backtick fiasco.

## ~10:32 - Middleware Matcher Fix for "The string did not match the expected pattern"

### Root Cause Found
- The error was NOT in the frontend or backend code — it was in `src/middleware.ts` matcher pattern
- Next.js 16 uses `URLPattern` API internally, which Safari doesn't support well with `\w` regex shorthand
- Old pattern: `['/((?!.+\.[\w]+$|_next).*)', '/', '/(api|trpc)(.*)']` — contains `\w` which Safari rejects
- **Fix:** Changed to `['/((?!api|_next/static|_next/image|favicon.ico).*)']` — simpler, no regex shorthand
